# 📊 Справочник метрик ручного тестирования производительности

---

## Таблица метрик

| Название метрики | Расшифровка | Для чего нужна | Где смотреть в DevTools | Допустимые значения |
|:---|:---|:---|:---|:---|
| **FCP** | First Contentful Paint | Понять, когда пользователь увидел **первый** намёк, что страница жива (буква, фон, иконка) | Lighthouse → отчёт Performance / Performance → метрики загрузки | **&lt; 1.8 с** — хорошо |
| **LCP** | Largest Contentful Paint | Понять, когда на экране появился **главный** контент (большая картинка или заголовок) | Lighthouse → отчёт Performance / Performance → Local metrics | **&lt; 2.5 с** — хорошо |
| **TTI** | Time to Interactive | Узнать, когда страница полностью готова **реагировать на клики** и ввод | Lighthouse → отчёт Performance | **&lt; 3.8 с** — хорошо |
| **TBT** | Total Blocking Time | Посчитать суммарное время, когда страница **«зависала»** из-за тяжёлого JavaScript | Lighthouse → отчёт Performance | **&lt; 200 мс** — хорошо |
| **CLS** | Cumulative Layout Shift | Увидеть, **насколько страница «прыгает»** при загрузке (текст уезжает из-за картинки или рекламы) | Lighthouse → отчёт Performance / Performance → Local metrics | **&lt; 0.1** — хорошо |
| **INP** | Interaction to Next Paint | Проверить, **сколько ждёт пользователь** от своего клика до появления результата на экране | Performance → Local metrics (вкладка Interactions) | **&lt; 200 мс** — хорошо |
| **SI** | Speed Index | Оценить, **насколько быстро визуально заполняется** экран контентом | Lighthouse → отчёт Performance | **&lt; 3.4 с** — хорошо |
| **TTFB** | Time To First Byte | Узнать, **сколько «думает» сервер**, прежде чем прислать первый байт ответа | Network → выбрать запрос → вкладка **Timing** → Waiting for server response | **&lt; 0.6 с** — хорошо |
| **DOM** | Document Object Model (количество элементов) | Оценить, **насколько «раздут» HTML** — сколько тегов нужно «переварить» браузеру | **Console** → ввести `document.querySelectorAll('*').length` | **&lt; 1500** — желательно |
| **Кол-во запросов** | Число HTTP-запросов к серверу | Понять, **сколько раз браузер «стучится»** на сервер за данными, картинками, скриптами | Network → нижняя строка статуса (`X requests`) | **Чем меньше, тем лучше** (желательно &lt; 50) |
| **Вес страницы** | Общий объём загруженных данных | Оценить, **сколько мегабайт «проглатывает»** браузер при открытии страницы | Network → нижняя строка статуса (`X MB transferred`) | **&lt; 1–2 МБ** — желательно |
| **FPS** | Frames Per Second (кадров в секунду) | Проверить, **не лагает ли прокрутка** и анимации на странице | Performance → Record → смотреть полосу **FPS** сверху | **60** — идеально, **&lt; 30** — заметные лаги |
| **Ошибки JS** | Сообщения об ошибках JavaScript | Найти **поломки в коде**, которые замедляют отрисовку и ломают логику | **Console** → красные и жёлтые сообщения | **0** — идеально |

## 🧭 Быстрая памятка: куда идти за ответом

| Если нужно узнать… | Идём сюда |
|:---|:---|
| 🔴 «Тормозит ли сервер?» | **Network** → Timing → *Waiting for server response* |
| 🟡 «Прыгает ли страница?» | **Lighthouse** → CLS / **Performance** → CLS |
| 🟢 «Когда появится главное?» | **Lighthouse** → LCP / **Performance** → LCP |
| 🔵 «Реагирует ли на клики?» | **Performance** → INP / **Lighthouse** → TTI |
| 🟣 «Сколько тегов в HTML?» | **Console** → `document.querySelectorAll('*').length` |
| 🟠 «Есть ли ошибки в коде?» | **Console** → красные / жёлтые сообщения |
| ⚫ «Общий балл здоровья страницы?» | **Lighthouse** → Performance (кружок с цифрой) |

| Балл | Зона | Значение |
|:---:|:---|:---|
| 90–100 | 🟢 Зелёная | Отлично |
| 50–89 | 🟡 Жёлтая | Нужно улучшить |
| 0–49 | 🔴 Красная | Плохо, требует срочного вмешательства |
